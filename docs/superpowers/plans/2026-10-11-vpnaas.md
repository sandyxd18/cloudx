# VPNaaS IPsec nyata Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans.

**Goal:** Koneksi VPN site-to-site benar-benar naik (strongSwan di netns per router, terikat ke OVN) dan trafik subnet lokal ↔ `peer_cidrs` terenkripsi ESP.

**Architecture:** API networking membuat objek OVN (LS transit, LRP, 2 LSP, rute statis) dan baris `networking_vpn_gateways`. `vpn-worker` (clone pola `lb_worker`) polling `/internal/vpn-agent/<host>`, membuat netns + 2 port internal `br-int` (`iface-id`), satu `charon` per netns, memuat `swanctl.conf`, melaporkan status.

**Spec:** `docs/superpowers/specs/2026-10-11-vpnaas-design.md`

## Global Constraints
- Config worker lewat `/etc/cloudx/vpn-worker/vpn-worker.conf` (`node_name`), bukan env di systemd.
- Setiap `except Exception` butuh `# best-effort: <alasan>`.
- PSK tidak pernah masuk log. File PSK mode 0600.
- Tanpa commit/push, tanpa `git checkout/stash/restore/reset`. Tanpa file scratch di root repo.
- Pola acuan: `services/lb_worker/app/main.py` (netns, port, tick, `internal_headers`), `routers/routing.py` (alokasi /30, `sync`, rollback), `ovn_cli.ovn`, `shared.auth_middleware.InternalAuth`.
- Tes jalan dengan env: `AUTH_SECRET_KEY`=x*32, `AUTH_ADMIN_PASSWORD=x`, `KEY_MANAGER_MASTER_KEY`=x*32, `REVOCATION_CHECK=false`.

## Task 3: API gateway + OVN (create/delete connection)
**Files:** `services/networking/app/routers/vpn.py`, `ovn_cli.py` (helper bila perlu), `tests/networking/test_vpn_gateway.py`
- [ ] Create: router milik caller; tanpa `external_network_id` → 400; `peer_cidrs` overlap dengan subnet router atau antar dirinya → 409; pilih/buat gateway (host = chassis gateway router, ambil dari `ovn-sbctl`/nilai `host` router yang ada; transit /30 berikutnya dari `100.101.0.0/16`, pool habis → 409; `outer_ip` dari alokasi external subnet yang tidak dipakai FIP/router/gateway lain, hindari `.100–.102` FIP yang ada dan `allocation_start-1`).
- [ ] Objek OVN idempotent (`--may-exist`): `ls-add vpn-<gw>`, `lrp-add <router> lrp-vpn-<gw> <mac> <.1/30>` + `lsp-add` tipe router (peer ke LRP), `lsp-add vpn-<gw> vpn-<gw>-in` (address mac+.2), LSP luar di LS external network `vpn-<gw>-out` (address mac outer_ip), `lr-route-add <router> <peer_cidr> <.2>` per CIDR. Gagal → rollback DB + `--if-exists` hapus semua objek (best-effort).
- [ ] Delete connection: hapus rute; koneksi terakhir → hapus LSP, LRP, LS, gateway.
- [ ] `admin_state_up=false` → keluar dari daftar worker, objek OVN tetap.
- [ ] `/internal/vpn-agent/{host}` (GET; `InternalAuth`; keluarkan gateway host itu + koneksi + kebijakan + PSK + subnet lokal router) dan `/internal/vpn-agent/{host}/status` (POST `{statuses:{conn_id:{status,reason}}}`).
- [ ] Tes dengan `ovn_cli.ovn` di-mock: objek dibuat, 400, 409 overlap, rollback bersih, gateway dihapus dengan koneksi terakhir, /30 unik. Mutasi: cabut guard overlap & cleanup rollback, tunjukkan tes gagal, pulihkan.
