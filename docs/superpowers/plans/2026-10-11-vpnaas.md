# Real IPsec VPNaaS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans.

**Goal:** A site-to-site VPN connection really comes up (strongSwan in a netns per router, bound to OVN) and the traffic local subnet ↔ `peer_cidrs` is ESP-encrypted.

**Architecture:** The networking API creates the OVN objects (transit LS, LRP, 2 LSPs, static route) and a `networking_vpn_gateways` row. `vpn-worker` (a clone of the `lb_worker` pattern) polls `/internal/vpn-agent/<host>`, creates the netns + 2 internal `br-int` ports (`iface-id`), one `charon` per netns, loads `swanctl.conf`, and reports the status.

**Spec:** `docs/superpowers/specs/2026-10-11-vpnaas-design.md`

## Global Constraints
- Worker config through `/etc/cloudx/vpn-worker/vpn-worker.conf` (`node_name`), not environment variables in systemd.
- Every `except Exception` needs `# best-effort: <reason>`.
- The PSK never reaches the log. The PSK file has mode 0600.
- No commit/push, no `git checkout/stash/restore/reset`. No scratch files in the repo root.
- Reference patterns: `services/lb_worker/app/main.py` (netns, port, tick, `internal_headers`), `routers/routing.py` (/30 allocation, `sync`, rollback), `ovn_cli.ovn`, `shared.auth_middleware.InternalAuth`.
- Tests run with env: `AUTH_SECRET_KEY`=x*32, `AUTH_ADMIN_PASSWORD=x`, `KEY_MANAGER_MASTER_KEY`=x*32, `REVOCATION_CHECK=false`.

## Task 3: Gateway API + OVN (create/delete connection)
**Files:** `services/networking/app/routers/vpn.py`, `ovn_cli.py` (helper if needed), `tests/networking/test_vpn_gateway.py`
- [ ] Create: the router belongs to the caller; without `external_network_id` → 400; `peer_cidrs` overlapping a router subnet or each other → 409; pick/create the gateway (host = the router's gateway chassis, taken from `ovn-sbctl`/the router's existing `host` value; the next transit /30 from `100.101.0.0/16`, pool exhausted → 409; `outer_ip` from the external subnet allocation that no FIP/router/other gateway uses, avoiding the existing FIPs `.100–.102` and `allocation_start-1`).
- [ ] Idempotent OVN objects (`--may-exist`): `ls-add vpn-<gw>`, `lrp-add <router> lrp-vpn-<gw> <mac> <.1/30>` + a router-type `lsp-add` (peer to the LRP), `lsp-add vpn-<gw> vpn-<gw>-in` (address mac+.2), the outer LSP on the external network's LS `vpn-<gw>-out` (address mac outer_ip), `lr-route-add <router> <peer_cidr> <.2>` per CIDR. Failure → roll back the DB + delete every object with `--if-exists` (best-effort).
- [ ] Delete connection: delete the routes; the last connection → delete the LSPs, LRP, LS, gateway.
- [ ] `admin_state_up=false` → out of the worker's list, the OVN objects stay.
- [ ] `/internal/vpn-agent/{host}` (GET; `InternalAuth`; returns that host's gateways + connections + policies + PSK + the router's local subnets) and `/internal/vpn-agent/{host}/status` (POST `{statuses:{conn_id:{status,reason}}}`).
- [ ] Tests with `ovn_cli.ovn` mocked: objects created, 400, 409 overlap, clean rollback, the gateway deleted with the last connection, unique /30. Mutation: remove the overlap guard & the rollback cleanup, show the tests fail, restore.
