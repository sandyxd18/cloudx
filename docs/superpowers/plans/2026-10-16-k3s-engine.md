# K3s Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn `k8s_engine` from a stub into a creator of real K3s clusters on CloudX VMs.

**Architecture:** The API only records the intent (`status`, `worker_count`). `k8s-engine-worker` (controller, polling every 5 s, `InternalAuth`) creates/deletes VMs through the compute API with K3s `user_data`; the VMs report ready through an internal callback. The image that contains K3s is baked once.

**Tech Stack:** FastAPI/SQLAlchemy/Alembic, compute API, K3s (air-gap), `qemu-nbd`.

**Spec:** `docs/superpowers/specs/2026-10-16-k3s-engine-design.md`. Pattern references: `services/orchestration_worker/app/main.py`, `services/networking/app/routers/bgp_agent.py`, `tests/k8s_engine/test_clusters.py`.

## Global Constraints

- No commit/push, no `git checkout/stash/restore/reset/clean/add/rm/apply/revert/switch`, no scratch files in the repo root. Only `git diff/status/log`.
- Every broad `except Exception` must carry `# best-effort: <reason>`; processes go through `shared.proc.run`, not `subprocess`.
- OpenStack-style configuration (`/etc/cloudx/k8s-engine-worker/k8s-engine-worker.conf`), not systemd environment variables.
- Tokens (`join_token`, `admin_token`) must not appear in logs or in the cluster list/get responses; only in the kubeconfig and `user_data`.
- Migration: `k8s_engine_0002`; the model and the migration must pass `tests/shared/test_migrations.py`.
- Docs are written in Indonesian, without emoji. *(Superseded: all documentation is now English.)*

## Review Focus

- A cluster deleted while still `CREATING`: every VM already created must be deleted too.
- Compute refuses to create a worker midway: status `ERROR` + `status_reason`, VMs already created are cleaned up.
- A repeated `ready` callback, or one from a cluster that was already deleted: idempotent / 404, not 500.
- `worker_count` lowered to 0 and raised again: the final number of nodes equals the requested number.
- The master never becomes ready: the timeout turns into `ERROR`, not `CREATING` forever.

### Task 1: Model, migration, API (stub becomes desired-state)

**Files:** Modify `services/k8s_engine/app/main.py`; Create `services/k8s_engine/migrations/versions/k8s_engine_0002_real_clusters.py`; Test `tests/k8s_engine/test_clusters.py`, `tests/k8s_engine/test_internal.py`.

**Interfaces:**
- Produces: columns `K8sCluster.join_token`, `admin_token`, `status_reason`, `master_ip`, `ready_at`; table `K8sNode(id, cluster_id, server_id, role, ip, ready)`; statuses `CREATING|ACTIVE|SCALING|DELETING|ERROR`.
- Produces endpoints: `GET /internal/k8s-engine/clusters` (all clusters with their `nodes`, including tokens), `POST /internal/k8s-engine/clusters/{id}/nodes` (the worker records a node: `server_id`, `role`), `POST /internal/k8s-engine/clusters/{id}/ready` (body `role`, `server_id`, `ip`), `POST /internal/k8s-engine/clusters/{id}/status` (the worker writes `status`, `status_reason`, `master_ip`), `DELETE /internal/k8s-engine/clusters/{id}` (delete the row). All `InternalAuth`.
- `POST /clusters` creates status `CREATING` with random tokens (`secrets.token_urlsafe(24)`); `DELETE /clusters/{id}` changes it to `DELETING` (the worker deletes the row); `POST /scale` changes `worker_count` and the status to `SCALING` if `ACTIVE`, 409 otherwise.

- [ ] **Step 2:** Internal tests (`TestClient` with `X-Internal-Token`): without the token 401; `ready` for an unknown cluster 404; `ready` twice is idempotent; the master's `ready` fills `master_ip`.
- [ ] **Step 3:** Implement the model, the migration and the endpoints; kubeconfig: `server: https://<master_ip>:6443`, `insecure-skip-tls-verify: true`, token `admin_token`.
- [ ] **Step 4:** `python -m pytest tests/k8s_engine tests/shared/test_migrations.py -q -W ignore` passes. Mutation check: remove the 409 check on scale, remove the token filtering in the list; both must make tests fail.

### Task 2: `k8s_cfg.py` (pure user_data functions)

**Files:** Create `services/shared/k8s_cfg.py`; Test `tests/shared/test_k8s_cfg.py`.

**Interfaces:**

- Master: write `/etc/rancher/k3s/token-auth` with `admin_token,admin,admin,system:masters`, run `k3s server --token <join_token> --tls-san <ip> --kube-apiserver-arg token-auth-file=...`; once `/readyz` is OK, `curl -X POST <callback_url>/internal/k8s-engine/clusters/<id>/ready` with the header `X-Internal-Token`. Worker: `k3s agent --server https://<master_ip>:6443 --token <join_token>` and then the callback.

- [ ] **Step 1:** Tests: the output starts with `#cloud-config`, contains the right master/agent argv and the callback URL; `render_*` rejects dangerous characters in `name` (only `[a-z0-9-]`, ValueError); tokens containing `'` or a newline are rejected.

### Task 3: `k8s-engine-worker`

**Files:** Create `services/k8s_engine_worker/app/__init__.py`, `services/k8s_engine_worker/app/main.py`, `etc/systemd/cloudx-k8s-engine-worker.service`; Test `tests/k8s_engine_worker/test_reconcile.py`.

**Interfaces:**
- Consumes: the Task 1 internal endpoints, `shared.k8s_cfg` from Task 2, compute `POST /servers` (payload `name`, `image`, `flavor`, `network`, `user_data`), `DELETE /servers/{id}`, `shared.internal.internal_headers`.
- Produces: an idempotent `tick()`. Rules per cluster:
  - `CREATING`: no master node -> create the master; master `ready` -> record `master_ip`, create `worker_count` workers; all `ready` -> `ACTIVE`; past `READY_TIMEOUT` (default 900 s from `created_at`) -> `ERROR` + reason.
  - `SCALING`: bring the worker count to the target (add / remove the newest), then `ACTIVE` once all are `ready`.
  - `DELETING`: delete every VM, then `DELETE` the cluster row.
  - `ERROR`: create no new VMs; the recorded VMs are deleted only when the cluster is deleted.
  - Compute failure during create: `ERROR`, VMs already created are deleted.

- [ ] **Step 1:** Tests with `run`/`requests` patched: the create order (master first, workers after the master is ready), scale up/down, `DELETING` deletes every VM before the row is deleted, delete during `CREATING` cleans up the VMs, a timeout becomes `ERROR`, a compute failure cleans up, a tick with no change does not call compute.
- [ ] **Step 2:** Implement; the systemd unit is copied from `cloudx-orchestration-worker.service` (rename names/directories).
- [ ] **Step 3:** Pass; mutation: skip the cleanup on failure, create workers before the master is ready, no timeout. Each mutation must make at least one test fail.
