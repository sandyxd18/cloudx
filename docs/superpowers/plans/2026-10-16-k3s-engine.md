# K3s Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Mengubah `k8s_engine` dari stub menjadi pembuat cluster K3s sungguhan di VM CloudX.

**Architecture:** API hanya mencatat niat (`status`, `worker_count`). `k8s-engine-worker` (controller, polling 5 s, `InternalAuth`) membuat/menghapus VM lewat compute API dengan `user_data` K3s; VM melapor siap lewat callback internal. Image berisi K3s di-bake sekali.

**Tech Stack:** FastAPI/SQLAlchemy/Alembic, compute API, K3s (airgap), `qemu-nbd`.

**Spec:** `docs/superpowers/specs/2026-10-16-k3s-engine-design.md`. Referensi pola: `services/orchestration_worker/app/main.py`, `services/networking/app/routers/bgp_agent.py`, `tests/k8s_engine/test_clusters.py`.

## Global Constraints

- Tanpa commit/push, tanpa `git checkout/stash/restore/reset/clean/add/rm/apply/revert/switch`, tanpa file scratch di root repo. Hanya `git diff/status/log`.
- Setiap `except Exception` lebar wajib `# best-effort: <alasan>`; proses via `shared.proc.run`, bukan `subprocess`.
- Konfigurasi gaya OpenStack (`/etc/cloudx/k8s-engine-worker/k8s-engine-worker.conf`), bukan env di systemd.
- Token (`join_token`, `admin_token`) tidak boleh ada di log atau di respons list/get cluster; hanya di kubeconfig dan `user_data`.
- Migrasi: `k8s_engine_0002`; model dan migrasi harus lolos `tests/shared/test_migrations.py`.
- Docs berbahasa Indonesia, tanpa emoji.

## Review Focus

- Cluster dihapus saat masih `CREATING`: semua VM yang sudah dibuat harus ikut terhapus.
- Compute menolak create worker di tengah jalan: status `ERROR` + `status_reason`, VM yang terlanjur dibuat dibersihkan.
- Callback `ready` berulang atau dari cluster yang sudah dihapus: idempoten / 404, bukan 500.
- `worker_count` diturunkan ke 0 dan dinaikkan lagi: jumlah node akhir sama dengan yang diminta.
- Master tidak pernah siap: timeout menjadi `ERROR`, bukan `CREATING` selamanya.

### Task 1: Model, migrasi, API (stub menjadi desired-state)

**Files:** Modify `services/k8s_engine/app/main.py`; Create `services/k8s_engine/migrations/versions/k8s_engine_0002_real_clusters.py`; Test `tests/k8s_engine/test_clusters.py`, `tests/k8s_engine/test_internal.py`.

**Interfaces:**
- Produces: kolom `K8sCluster.join_token`, `admin_token`, `status_reason`, `master_ip`, `ready_at`; tabel `K8sNode(id, cluster_id, server_id, role, ip, ready)`; status `CREATING|ACTIVE|SCALING|DELETING|ERROR`.
- Produces endpoint: `GET /internal/k8s-engine/clusters` (semua cluster beserta `nodes`, termasuk token), `POST /internal/k8s-engine/clusters/{id}/nodes` (worker mencatat node: `server_id`, `role`), `POST /internal/k8s-engine/clusters/{id}/ready` (body `role`, `server_id`, `ip`), `POST /internal/k8s-engine/clusters/{id}/status` (worker menulis `status`, `status_reason`, `master_ip`), `DELETE /internal/k8s-engine/clusters/{id}` (hapus baris). Semua `InternalAuth`.
- `POST /clusters` membuat status `CREATING`, token acak (`secrets.token_urlsafe(24)`); `DELETE /clusters/{id}` mengubah ke `DELETING` (baris dihapus worker); `POST /scale` mengubah `worker_count` dan status `SCALING` bila `ACTIVE`, 409 selain itu.

- [ ] **Step 1:** Tes: create mengembalikan `CREATING` tanpa `join_token`/`admin_token`; list/get tidak memuat token; scale pada `CREATING` memberi 409; delete memberi 202/204 dan status `DELETING`; kubeconfig pada cluster non-`ACTIVE` memberi 409.
- [ ] **Step 2:** Tes internal (`TestClient` dengan `X-Internal-Token`): tanpa token 401; `ready` untuk cluster tak dikenal 404; `ready` dua kali idempoten; `ready` master mengisi `master_ip`.
- [ ] **Step 3:** Implementasi model, migrasi, endpoint; kubeconfig: `server: https://<master_ip>:6443`, `insecure-skip-tls-verify: true`, token `admin_token`.
- [ ] **Step 4:** `python -m pytest tests/k8s_engine tests/shared/test_migrations.py -q -W ignore` lulus. Mutation check: hapus pengecekan 409 pada scale, hapus penyaringan token di list; keduanya harus menggagalkan tes.

### Task 2: `k8s_cfg.py` (fungsi murni user_data)

**Files:** Create `services/shared/k8s_cfg.py`; Test `tests/shared/test_k8s_cfg.py`.

**Interfaces:**
- Produces: `render_master(cluster_id: str, name: str, join_token: str, admin_token: str, callback_url: str, internal_token: str) -> str` dan `render_worker(cluster_id: str, master_ip: str, join_token: str, callback_url: str, internal_token: str) -> str`; keduanya cloud-config `#cloud-config`.
- Master: tulis `/etc/rancher/k3s/token-auth` dengan `admin_token,admin,admin,system:masters`, jalankan `k3s server --token <join_token> --tls-san <ip> --kube-apiserver-arg token-auth-file=...`; setelah `/readyz` OK `curl -X POST <callback_url>/internal/k8s-engine/clusters/<id>/ready` dengan header `X-Internal-Token`. Worker: `k3s agent --server https://<master_ip>:6443 --token <join_token>` lalu callback.

- [ ] **Step 1:** Tes: output diawali `#cloud-config`, memuat argv master/agent yang tepat dan URL callback; `render_*` menolak karakter berbahaya pada `name` (hanya `[a-z0-9-]`, ValueError); token yang mengandung `'` atau newline ditolak.
- [ ] **Step 2:** Implementasi tanpa dependensi baru.
- [ ] **Step 3:** Lulus; mutation check: hapus validasi karakter, hapus header token pada callback.

### Task 3: `k8s-engine-worker`

**Files:** Create `services/k8s_engine_worker/app/__init__.py`, `services/k8s_engine_worker/app/main.py`, `etc/systemd/cloudx-k8s-engine-worker.service`; Test `tests/k8s_engine_worker/test_reconcile.py`.

**Interfaces:**
- Consumes: endpoint internal Task 1, `shared.k8s_cfg` Task 2, compute `POST /servers` (payload `name`, `image`, `flavor`, `network`, `user_data`), `DELETE /servers/{id}`, `shared.internal.internal_headers`.
- Produces: `tick()` yang idempoten. Aturan per cluster:
  - `CREATING`: tanpa node master -> buat master; master `ready` -> catat `master_ip`, buat worker sebanyak `worker_count`; semua `ready` -> `ACTIVE`; lewat `READY_TIMEOUT` (default 900 s dari `created_at`) -> `ERROR` + alasan.
  - `SCALING`: samakan jumlah worker (tambah/hapus yang terbaru), lalu `ACTIVE` bila semua `ready`.
  - `DELETING`: hapus semua VM, lalu `DELETE` baris cluster.
  - `ERROR`: tidak membuat VM baru; VM yang tercatat dihapus hanya saat cluster dihapus.
  - Gagal compute saat create: `ERROR`, VM yang terlanjur dibuat dihapus.

- [ ] **Step 1:** Tes dengan `run`/`requests` dipatch: urutan create (master dulu, worker setelah master ready), scale naik/turun, `DELETING` menghapus semua VM sebelum baris dihapus, delete saat `CREATING` membersihkan VM, timeout menjadi `ERROR`, compute gagal membersihkan, tick tanpa perubahan tidak memanggil compute.
- [ ] **Step 2:** Implementasi; unit systemd disalin dari `cloudx-orchestration-worker.service` (ganti nama/direktori).
- [ ] **Step 3:** Lulus; mutation: lewati cleanup saat gagal, buat worker sebelum master ready, tanpa timeout. Tiap mutasi harus menggagalkan >= 1 tes.
