# BGP (BIRD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make `bgp-peers` real: an eBGP session through BIRD in a netns per router, advertise the `advertised_prefixes`, and put the learned routes into OVN.

**Architecture:** The same pattern as VPNaaS: `bgp-worker` polls `/internal/bgp-agent/{host}` every 5 s, runs one `bird` per router in the netns `qbgp-<short>`, reports status + routes; the API reconciles the routes into OVN.

**Tech Stack:** FastAPI/SQLAlchemy/Alembic, OVN (`ovn_cli`), `shared.proc.run`, bird2 2.14.

**Spec:** `docs/superpowers/specs/2026-10-12-bgp-design.md`. Spike: `docs/superpowers/plans/bgp-spike-notes.md`. Code references: `services/networking/app/routers/vpn.py`, `services/vpn_worker/app/main.py`, `tests/vpn_worker/test_reconcile.py`, `tests/networking/test_vpn_gateway.py`.

## Global Constraints

- No commit/push, no `git checkout/stash/restore/reset`, no scratch files in the repo root.
- Every broad `except Exception` must carry `# best-effort: <reason>`; call processes through `shared.proc.run`, not `subprocess`.
- Internal endpoints use `dependencies=[InternalAuth]` (not a manual string token). The worker sends the keys `status` and `status_reason`; the endpoint reads the same keys.
- Speaker host = the chassis hostname (`vpn._get_router_host(router.name)`), not the UUID.
- The password never reaches the log/argv; the `bird.conf` file has mode 0600.
- The worker tests patch `bgp_worker.run` (the name the worker imports), not `shared.proc.run`, and assert the exact argv. Every invariant has a mutation check that is shown to fail.
- Short id: `gw_id.split("-",1)[1][:8]`; speaker ID `bgpsp-<12 hex>`; Linux ifnames <= 15 characters.
- The model and the migration must be identical (`tests/shared/test_migrations.py`); no FK on the extra columns of `networking_bgp_peers` (SQLite cannot ALTER constraints).
- Always run the FULL SUITE before reporting: `python -m pytest tests/networking tests/shared tests/cli tests/bgp_worker tests/vpn_worker -q -W ignore` with env `AUTH_SECRET_KEY=x*32`, `AUTH_ADMIN_PASSWORD=x`, `KEY_MANAGER_MASTER_KEY=x*32`, `REVOCATION_CHECK=false`, `STORAGE_LVM_DRIVER=true`; plus `ruff check services cli tests --select F401,F811,F821 --exclude "node_modules,migrations/versions"`.

## Review Focus

- A router without an external gateway: 400, no OVN objects left.
- Two peers on the same router with different `local_as`: 409.
- The last peer deleted while learned routes exist: every OVN route owned by the peer is withdrawn before the speaker is deleted.
- Peer `down` / bird dead: learned routes are withdrawn, other static routes on the router are not touched.
- A learned route that is a default (`0.0.0.0/0`), overrides a router subnet, or has a next hop outside the external subnet: ignored.
- Worker restart: re-adopt the existing netns/port/bird without duplicates.

**Interfaces:**
