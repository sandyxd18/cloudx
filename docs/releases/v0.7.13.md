# CloudX v0.7.13

Fase 1 (core parity) release, covering the internal milestones v0.7.10 to v0.7.13. There are **upgrade steps**.

## Upgrading from v0.7.9

1. Config moved from `/etc/cloudx/cloudx.env` and systemd `Environment=` lines to OpenStack-style files: `/etc/cloudx/cloudx.conf` (shared) and `/etc/cloudx/<service>/<service>.conf` (per service, wins). Keys are the lowercase env-var names (`internal_token = ...`). Systemd units no longer carry `Environment=`; re-run `scripts/install-systemd.sh`.
2. Run `cloudx-db-migrate` on the controller: `auth_0002`, `auth_0003`, `networking_0002`, `networking_0003`, `image_0002`, `compute_0002`.
3. Restart the compute-worker on every compute/storage node (new handler `relocate_out`).

## Security and isolation (v0.7.10)
- Placement is the scheduler: `POST /internal/claim` picks the provider with the most free memory; server groups map to `exclude_hosts` / `only_hosts`. Compute falls back to least-servers when Placement is down.
- `reader` role: GET/HEAD/OPTIONS only.
- Neutron resources carry `project_id`; another project's resource is a 404. Legacy rows without a project stay visible.
- Keystone role assignments (`PUT/DELETE /projects/{p}/users/{u}/roles/{role}`, `GET /role-assignments`). Access-key tokens are scoped to the key's project.
- Security-group rules honour `ethertype` IPv6 (`ip6`/`icmp6`, ND allowed).

## Data plane (v0.7.11)
- Neutron: `allowed_address_pairs`, router `routes`, network `mtu`, per-project network quotas (HTTP 413).
- Cinder: `revert` to the newest snapshot (LVM), `os-retype` within one backend.
- Glance: `queued`/`saving`/`active` status machine, `qemu-img` format inspection, `virtual_size`, `os_hash_algo`/`os_hash_value`, `min_ram_mb`, `protected`, custom `properties`.

## Nova operations (v0.7.12)
- Flavor `extra_specs` (`/flavors/{ref}/os-extra_specs`); `aggregate_instance_extra_specs:<k>` is matched against aggregate metadata.
- Aggregates: `set_metadata`; `GET /os-availability-zone`; `availability_zone` on server create.
- `GET /limits`, `GET/PUT /os-quota-sets/{project}` (a view over auth-api quota).
- `GET /servers/{ref}/os-instance-actions`.
- `GET /os-services`, `PUT /os-services/{host}` (`disabled`, `forced_down`); disabled hosts are skipped by the scheduler.
- `POST /servers/{ref}/migrate` (cold) and `/evacuate` (source must be `forced_down`).

## Known limitations
- Migrate and evacuate refuse servers with data volumes attached, and migrate always ends ACTIVE.
- Evacuate assumes the source host is really dead. If its worker is still alive, the old libvirt domain keeps running on the same volume; destroy it manually (`virsh destroy`) before un-forcing the host. Verified on the lab: it is not auto-cleaned.
- Instance actions record the request, not its outcome.
- Neutron names are still globally unique; `trunks`, `routing` and `vpn` routers are not owner-checked.
- Domains are labels only. No dashboard or CLI for role assignments or the new quota fields.
- VPN, BGP, replication, scheduled snapshots and the K8s engine remain control-plane records.
