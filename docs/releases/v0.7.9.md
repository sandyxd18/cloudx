# CloudX v0.7.9

Hardening release (v0.7.7 and v0.7.8 were skipped). There are **upgrade steps**.

## Upgrading from v0.7.6

1. Every node needs the same `INTERNAL_TOKEN` in `/etc/cloudx/cloudx.env` (the installer generates one; copy it to the other nodes). `/internal/*`, image PATCH/DELETE/list from workers, and metadata identity hints require it.
2. Install the new units `cloudx-image-worker` and `cloudx-orchestration-worker` and `systemctl enable --now` them on the controller.
3. Browsers: set `CORS_ORIGINS` if a UI is served from another origin. `*` is no longer the default on any API.
4. Restart conductor (new handlers `create_snapshot_record`, `update_cgsnapshot`).

## Security
- Service-to-service `/internal/*` routes need `X-Internal-Token` or an admin JWT; logout revokes tokens; project scoping on volumes and servers; admin-only placement writes, flavor create and audit log; object-store path and bucket validation.
- `/metrics` token protected on all 14 APIs; the installer writes `/etc/prometheus/metrics_token`; Prometheus scrapes every API.

## Fixed
- Async image import (`POST /v2/tasks`) works end to end; the reconciler reads `items` and authenticates.
- Auto-scaling: worker payloads match compute-api, `POST /scaling-groups/{id}/history` records events and instances, `active_only` is honoured, LB pools got `POST/DELETE /pools/{id}/members`.
- Project quota counts live servers from compute's own table (placement usage was always empty, so quota never rejected).
- Consistency-group snapshots no longer fail silently (conductor handlers were missing).
- LVM: udev keys valid for LVM 2.03, snapshots without `-W y`.
- CLI: `server port add --network/--port`; e2e scripts use the unified CLI.

## Known limitations
- K8s engine, VPN, BGP, replication and scheduled snapshots are control-plane records only (K8s is labelled EXPERIMENTAL in its API title).
- Default DB credentials `cloudx:cloudx` in `shared/db.py` are for the lab only; set `DATABASE_URL`.
- `Router.project_id` is not stored; peering/BGP ownership is inferred.
- Service-to-service calls still use an admin login.
