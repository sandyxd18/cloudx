# CloudX v0.7.20

Domain isolation in the auth service, L7 parity for the ALB, and dashboard pages for stacks, alarms and role assignments. There are **upgrade steps**.

## Upgrading from v0.7.19
1. Copy `services/` and `cli/` to the controller, run `cloudx-db-migrate auth` (`auth_0004`) and `cloudx-db-migrate load_balancer` (`load_balancer_0004`), restart `cloudx-auth-api` and `cloudx-load-balancer-api`.
2. Copy `services/shared` and restart `cloudx-lb-worker` on every host that runs it (the haproxy renderer changed).
3. Rebuild the dashboard (`npm run build` in `services/dashboard/frontend`) and copy `dist/` to `services/dashboard/app/static`, plus `services/dashboard/app/main.py`; restart `cloudx-dashboard`.

## Changes
- `domain_id` on projects and users (default `default`); users get `is_domain_admin`. Tokens carry `domain_id` and `domain_admin`; the token role stays `member`.
- A domain admin manages projects, users, groups and role assignments inside its own domain only. Other domains answer 404; cross-domain create/assign answers 409; cross-domain login or `switch-project` answers 403.
- A domain admin cannot create or change domains, set quotas, create `admin` or domain-admin users, or escalate itself.
- A disabled domain blocks login. A domain with projects or users cannot be deleted (409).
- CLI: `project-create --domain`, `user-create --domain-admin`.
- **L7 parity (ALB)**: policy actions `REDIRECT_TO_URL` and `REDIRECT_PREFIX` (`redirect_http_code` 301/302/303/307/308); rule types `FILE_TYPE`, `HEADER`, `COOKIE` (with `key`); compare types `CONTAINS` and `REGEX`; `invert` and `admin_state_up` on rules, `admin_state_up` on policies; `GET` and `PUT` for policies and rules; CLI `l7policy show/update`, `l7rule show/update`. Migration `load_balancer_0004`.
- **Dashboard**: new pages Stacks (create, delete, suspend, resume, resources, events, outputs), Alarms (create, delete, history), Role assignments (assign, remove; domain admins allowed), and an L7 policies/rules section on the ALB listener of the load-balancer detail page.
- Installer scripts: `bash -n` passes on all of `scripts/*.sh`, and the `tests/scripts` checks (cleanup `--dry-run`, `prepare-lvm-node`, `build-k3s-image`) pass on a lab VM with real bash.

## Known limitations
- NLB `ROUND_ROBIN` / `LEAST_CONNECTIONS` are hash-based (OVN has no connection counter, same as the Octavia OVN provider; use an ALB).
- L7 `REGEX` uses haproxy (POSIX ERE) syntax, not PCRE. Redirect URLs cannot contain `%`, `$`, `{` or quotes (haproxy would expand them). Octavia's `SSL_*` rule types are not supported.
- Project names and usernames stay globally unique.
- No per-domain quota or billing.
- Other services do not filter by domain; isolation goes through the project.
- The system admin stays global.
- The dashboard has no domain picker. Stack create takes a text template only (no preview or update); L7 policies cannot be edited from the form (create, delete, enable/disable only). The dashboard pages have no automated tests (the repo has no frontend test setup).
- `http-request` actions (redirect, reject) run before `use_backend` in haproxy, so they win over pool routing whatever the policy position.
- Installer scripts that change the host (`install-systemd.sh`, `node-bootstrap.sh`, `setup-*.sh`, `prepare-host-libvirt.sh`) were syntax-checked but not run end to end on a fresh VM.
- The `v0.7.19` tag was not moved to the later test-only fix commits.
