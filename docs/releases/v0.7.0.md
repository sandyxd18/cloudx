# CloudX v0.7.0

This release tidies the code foundations and security after v0.6.0: there are no new API features, but there are
**changes that require upgrade steps** (see "Upgrading from v0.6.0").

## Upgrading from v0.6.0

1. **Secrets are mandatory.** There are no default secrets any more (`admin123`,
   `cloudx-secret-key-change-in-production...`). Services refuse to start without `AUTH_SECRET_KEY`,
   `AUTH_ADMIN_PASSWORD`, and `KEY_MANAGER_MASTER_KEY`. `scripts/install-systemd.sh` creates
   `/etc/cloudx/cloudx.env` (mode 640) with random values. In a multi-node deployment, **copy the same file** to every
   node that runs an API service before running the installer there. The new admin password is in that file, and old
   tokens are no longer valid.
2. **Database schema through Alembic.** Services no longer create or alter tables themselves and refuse to start if the
   schema has not been migrated. On the control plane run `sudo make migrate` (the installer does this automatically
   on nodes that host PostgreSQL). It is safe to run on an existing database: the baseline is idempotent and patches
   columns/data from earlier releases. Do this **before** restarting services.
3. **`shared` is now a Python package.** The installer installs it into the venv (`pip install /opt/cloudx/services`);
   `PYTHONPATH` in the systemd units is no longer needed. For a manual install, see steps 3-6 in `SETUP.md`.
4. **Volume quotas are now enforced.** The `max_volume_gb` check against auth-api never ran before (a latent bug);
   projects that are already over their limit will be rejected when creating new volumes.
5. **CLI:** `python cli/cloudx_cli/main.py` can no longer be run directly; use the `cloudx` command (pip) or
   `cd cli && python -m cloudx_cli.main`.

## Security
- Secrets and the admin password have no defaults (above); key-manager no longer accepts forged `X-Role`/`X-Project-Id`
  headers as authentication; `k8s_engine` now uses the JWT (it previously trusted `X-Project-Id` without
  authentication).
- The `cloudx service ...` CLI no longer uses `os.system` (command injection through the service name).
- MinIO credentials for backups no longer appear on the command line, in logs, or in the backup `error_message`.
- All external command calls go through `shared.proc`: arguments are lists (no shell), there is always a timeout, and
  secrets are masked in error messages.

## Bug fixes
- **Reconcilers** (block-store, networking, image) treated a failed check as "resource missing" and could mark healthy
  volumes `error` or delete `deleting` records. A failed check now means "unknown" and the record is skipped.
- IPv6 /64 (and IPv4 /8) subnets hung because every host address was enumerated.
- Deleting a network/subnet that was still in use removed the OVN switch first and then failed in the database (OVN and
  DB out of sync); it now returns 409.
- Deleting a placement resource provider that had inventories returned 500; the inventories are now removed too, or
  409 is returned while allocations still exist.
- `placement /healthcheck` and the domain-lookup fallback in compute-worker used undefined names.
- Volume restore ignored `dd` failures; billing/telemetry seeding failed on non-empty tables and duplicated rating
  sheets when two workers started at the same time.

## Internal changes
- Large `main.py` files were split by responsibility (networking, compute, block_store, auth, and the CLI); the API is
  unchanged (OpenAPI and route order are identical).
- Per-service Alembic migrations (`cloudx-db-migrate`), version table `alembic_version_<service>`.
- Error handling: `except Exception` handlers that swallowed errors are now logged or narrowed; a guard test enforces it.
- Tests are organised per service; `pytest` only runs unit tests without a lab (`--live` for tests against the lab),
  GitHub Actions CI, `make test|test-live|lint`.
- Removed: the `block_store/app/drivers` driver (a dead copy of the worker drivers).
- New documentation: `docs/README.md` (index), `docs/code-structure.md`.
