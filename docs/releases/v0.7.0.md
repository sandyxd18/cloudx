# CloudX v0.7.0

Rilis ini merapikan fondasi kode dan keamanan setelah v0.6.0: tidak ada fitur API baru, tetapi ada **perubahan yang
mewajibkan langkah upgrade** (lihat "Upgrade dari v0.6.0").

## Upgrade dari v0.6.0

1. **Secret wajib.** Tidak ada lagi secret bawaan (`admin123`, `cloudx-secret-key-change-in-production...`). Service
   gagal start tanpa `AUTH_SECRET_KEY`, `AUTH_ADMIN_PASSWORD`, dan `KEY_MANAGER_MASTER_KEY`. `scripts/install-systemd.sh`
   membuat `/etc/cloudx/cloudx.env` (mode 640) berisi nilai acak. Pada deployment multi-node, **salin file yang sama**
   ke setiap node yang menjalankan service API sebelum menjalankan installer di sana. Password admin baru ada di file
   itu, dan token lama tidak berlaku lagi.
2. **Skema database lewat Alembic.** Service tidak lagi membuat atau mengubah tabel sendiri dan menolak start kalau
   skema belum dimigrasi. Di control plane jalankan `sudo make migrate` (installer melakukannya otomatis di node yang
   punya PostgreSQL). Aman dijalankan pada database lama: baseline bersifat idempoten dan menambal kolom/data dari rilis
   sebelumnya. Lakukan **sebelum** me-restart service.
3. **`shared` menjadi paket Python.** Installer memasangnya ke venv (`pip install /opt/cloudx/services`); `PYTHONPATH`
   di unit systemd tidak diperlukan lagi. Instalasi manual: lihat langkah 3-6 di `SETUP.md`.
4. **Quota volume kini ditegakkan.** Pengecekan `max_volume_gb` terhadap auth-api sebelumnya tidak pernah berjalan
   (bug laten); project yang sudah melewati batasnya akan ditolak saat membuat volume baru.
5. **CLI:** `python cli/cloudx_cli/main.py` tidak bisa lagi dijalankan langsung; pakai perintah `cloudx` (pip) atau
   `cd cli && python -m cloudx_cli.main`.

## Keamanan
- Secret dan password admin tanpa default (di atas); key-manager tidak lagi menerima header `X-Role`/`X-Project-Id`
  palsu sebagai autentikasi; `k8s_engine` kini memakai JWT (sebelumnya mempercayai `X-Project-Id` tanpa autentikasi).
- CLI `cloudx service ...` tidak lagi memakai `os.system` (command injection lewat nama service).
- Kredensial MinIO untuk backup tidak lagi muncul di baris perintah, di log, atau di `error_message` backup.
- Semua pemanggilan perintah eksternal lewat `shared.proc`: argumen berupa list (tanpa shell), selalu ada timeout,
  secret disamarkan di pesan error.

## Perbaikan bug
- **Reconciler** (block-store, networking, image) menganggap pengecekan yang gagal sebagai "resource hilang" dan bisa
  menandai volume sehat `error` atau menghapus record `deleting`. Sekarang pengecekan yang gagal berarti "tidak
  diketahui" dan record dilewati.
- Subnet IPv6 /64 (dan IPv4 /8) menggantung karena semua alamat host dienumerasi.
- Menghapus network/subnet yang masih dipakai menghapus switch OVN lebih dulu lalu gagal di database (OVN dan DB tidak
  sinkron); sekarang 409.
- Menghapus resource provider placement yang punya inventory mengembalikan 500; sekarang inventory ikut terhapus, atau
  409 bila masih ada allocation.
- `placement /healthcheck` dan fallback pencarian domain di compute-worker memakai nama yang tidak terdefinisi.
- Restore volume mengabaikan kegagalan `dd`; seeding billing/telemetry gagal pada tabel berisi dan menggandakan
  rating sheet saat dua worker start bersamaan.

## Perubahan internal
- `main.py` besar dipecah per tanggung jawab (networking, compute, block_store, auth, dan CLI); API tidak berubah
  (OpenAPI dan urutan route identik).
- Migrasi Alembic per service (`cloudx-db-migrate`), tabel versi `alembic_version_<service>`.
- Penanganan error: handler `except Exception` yang menelan error dilog atau dipersempit; ada tes penjaga.
- Tes diatur per service, `pytest` hanya menjalankan tes unit tanpa lab (`--live` untuk tes terhadap lab), CI GitHub
  Actions, `make test|test-live|lint`.
- Dihapus: driver `block_store/app/drivers` (salinan mati dari driver worker).
- Dokumentasi baru: `docs/README.md` (indeks), `docs/code-structure.md`.
