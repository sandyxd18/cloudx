# CloudX v0.8.0

New DNS service (Designate-like, on BIND9), listener client CRL, and fixes. There are **upgrade steps**.

## Upgrading from v0.7.21
1. Controller: `apt install bind9 bind9utils`, `systemctl disable --now named`, then re-run `scripts/install-systemd.sh` (it installs the four DNS units and an AppArmor local rule for `/var/lib/cloudx/dns`). Add the `dns_*` keys from `etc/cloudx/cloudx.conf.sample` to `/etc/cloudx/cloudx.conf`.
2. Run `cloudx-db-migrate` for `auth` (`auth_0007` DNS quota), `dns` (`dns_0001`) and `load_balancer` (`load_balancer_0006`). From `/tmp`.
3. Copy `services/shared` to every host and restart the API units on the controller and `cloudx-lb-worker` on compute hosts. Rebuild the dashboard.
4. Enable `cloudx-dns-api`, `cloudx-dns-worker`, `cloudx-named-auth`, `cloudx-named-resolver` on the controller only.

## Changes
- **DNS service** (`dns-api` :8016, `dns-worker`, CLI `cloudx dns`, dashboard DNS page). Zones and recordsets (A, AAAA, CNAME, MX, TXT, SRV, NS, PTR), public or internal zones, per-project visibility and quota (`max_zones`, `max_recordsets`). Zone changes show `PENDING` until the worker has loaded them into BIND, then `ACTIVE`.
- **Two BIND instances** on the controller: `named-auth` (authoritative, no recursion, 172.20.0.120) and `named-resolver` (recursive for tenants, internal zones and forwarders, 172.20.0.118). Internal zones are never loaded into `named-auth`.
- **Secondaries**: a public zone can list secondary servers by IP; they may AXFR it and get NOTIFY. CloudX is always the primary.
- **Automatic names** under the platform domain `cloud.lab`: floating IP `<ip-dashed>.compute.cloud.lab`, load balancer with floating IP `<name>-<6 id>.elb.cloud.lab`, bucket `<bucket>-<8 project id>.s3.cloud.lab` (these three on both servers), and `<name>.<project>.internal.cloud.lab` for servers and load balancer VIPs (resolver only). They are created by the owning service on create/delete and reconciled by a 60 s sweep; a DNS failure never fails the resource. These records are read-only (409 on edit).
- **Subnets** created without `dns_nameservers` now get the platform resolver (existing subnets are unchanged).
- **Listener client CRL**: `client_crl_pem` on HTTPS listeners (`--client-crl-file`).
- **Fixes**: `all_tenants` load balancer listing leak, `cloudx-db-migrate` from a service directory, compute domain-quota race (second check under the lock), shared `check_domain_caps`, CRL expiry check.

## Known limitations
- CloudX DNS is not Designate 1:1: no TSIG, no DNSSEC, no secondary-type zones (CloudX is primary only), no zone transfer/import API, no floating IP PTR reverse records, no pools or blacklists. The API paths differ from `/v2/zones`.
- The platform zones are fixed (`cloud.lab` and four sub-zones); the base domain is a deployment setting and changing it later is not migrated.
- Bucket names resolve to the object-store host, but a DNS A record carries no port; clients still need the object-store port.
- Server and internal load balancer names appear up to 60 s after creation (sweep), and project names with characters that are invalid in DNS labels are slugged.
- The resolver ACL (`dns_resolver_clients`) must include the compute/gateway node network: tenant traffic is source-NATed to the node address (seen in the lab). The default also admits the whole 172.16.0.0/12 range, so any host there can recurse through the resolver. This was checked only from inside the lab, not from an outside network.
- The resolver runs with `dnssec-validation no` because forwarders strip DNSSEC data.
- Both BIND instances share the controller's two NICs on one subnet; replies to some clients may leave via the other interface.
- The CRL is static: it is not refreshed automatically, and an expired CRL makes haproxy reject every client certificate.
- Everything from v0.7.21 still applies (NLB algorithms, L7 REGEX syntax, domain quota as a CloudX extension, object store/k8s-engine/placement not covered by domain-admin visibility), except "no CRL support".
