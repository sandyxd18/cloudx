# CloudX v0.7.21

L7 ordering fix for the ALB, and dashboard follow-ups from v0.7.20. There are **upgrade steps**.

## Upgrading from v0.7.20
1. Run `cloudx-db-migrate` for `auth` (`auth_0005` unique names per domain, `auth_0006` domain quotas) and `load_balancer` (`load_balancer_0005`). From `/tmp`, not from `/opt/cloudx/services`.
2. Copy `services/shared` to every host (site-packages `shared/`) and restart `cloudx-lb-worker` where it runs; restart the API units on the controller.
3. Rebuild the dashboard (`npm run build` in `services/dashboard/frontend`), copy `dist/` to `services/dashboard/app/static`, restart `cloudx-dashboard`.

## Changes
- **L7 policy order (fix)**: the first matching policy now wins, whatever its action. Pool policies set `txn.pool`, later policies skip once it is set, and one `use_backend` applies it. Checked with real haproxy traffic.
- **Octavia `SSL_*` L7 rules**: `SSL_CONN_HAS_CERT`, `SSL_VERIFY_RESULT`, `SSL_DN_FIELD` (key = DN field such as `CN`). They need an HTTPS listener that asks for client certificates: new listener fields `client_authentication` (`NONE|OPTIONAL|MANDATORY`) and `client_ca_pem` (CLI `--client-authentication`, `--client-ca-file`). With `OPTIONAL`, a certificate that fails verification still connects, so `SSL_VERIFY_RESULT` rules can route it. Checked with real haproxy and real client certificates (none, valid, untrusted).
- **Names unique per domain**: project names and usernames are unique inside a domain, not globally (email stays global). Login takes an optional `domain`; an ambiguous name across domains returns 409 (use the id or a domain).
- **Domain quota**: `GET/PUT/DELETE /v3/domains/{id}/quota` set aggregate caps over all projects of a domain (instances, vCPUs, RAM, volume GB, networks, subnets, ports, routers, floating IPs, security groups). Only the system admin sets them; a domain admin reads its own. Enforced in compute, block-store and networking on top of the per-project quota.
- **Domain billing and visibility**: `?domain_id=` on `/billing/usage-records`, `/billing/invoices`, `/billing/summary`; `POST /billing/invoices?domain_id=` creates one consolidated invoice (stored as project `domain:<id>`). Domain admins see every project of their domain in compute servers, block-store volumes, networking and billing.
- **Quota check fix**: compute and block-store called the user route of auth for quotas, which rejects service calls (401), so the volume quota was silently skipped. They now use `/internal/projects/{id}/quota`.
- **Installer**: tested end to end on a fresh Ubuntu 24.04 VM (2 vCPU, 4 GB, 15 GB): all 16 units active, migrations applied, admin login works. `setup-storage.sh` wrote a 30 GB image regardless of disk size; the size is now `CLOUDX_VG_SIZE_MB` and a failed write removes the partial file.
- **Dashboard**: edit an L7 policy; preview and update a stack; a domain picker on project create and a domain-admin checkbox on user create. The API client has `node --test` tests (`npm test`).

## Known limitations
- NLB `ROUND_ROBIN` / `LEAST_CONNECTIONS` are hash-based (OVN has no connection counter, same as the Octavia OVN provider; use an ALB).
- L7 `REGEX` uses haproxy (POSIX ERE) syntax, not PCRE. Redirect URLs cannot contain `%`, `$`, `{` or quotes (haproxy would expand them).
- The system admin stays global.
- The dashboard domain picker only covers project and user create; there is no domain create, edit or delete page. The frontend tests cover the API client, not the page components.
- Only `install-systemd.sh` (with `setup-storage.sh`) was run on a fresh VM; `node-bootstrap.sh`, the other `setup-*.sh` and `prepare-host-libvirt.sh` were not.
- Domain caps are checked when a resource is created (not when a project is created). Checks take a Postgres advisory lock per domain; it only serialises parallel creates when the check and the insert commit in the same transaction (true for networking and block-store, not guaranteed for compute host claims).
- Domain-admin visibility covers compute, block-store, networking, billing, image, load balancer, orchestration, telemetry, event and key manager. Object store (buckets are addressed by name per project), k8s-engine and placement still scope to the caller's project.
- `PUT /listeners/{id}` changes `client_authentication` / `client_ca_pem`; the dashboard has a Domains tab (create, delete, quota).
- Listener client certificates are set at create time only (no listener update); no CRL support.
- The dashboard has no page for domain quotas.
- The `v0.7.19` tag was not moved to the later test-only fix commits.
