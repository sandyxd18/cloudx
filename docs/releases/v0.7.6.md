# CloudX v0.7.6

Closes the open items left after v0.7.5. There are **upgrade steps** (see below).

## Upgrading from v0.7.5

1. **`METRICS_TOKEN`**: `/metrics` on every API now answers 401 unless it gets `Authorization: Bearer $METRICS_TOKEN`.
   The installer adds a random `METRICS_TOKEN` to new `/etc/cloudx/cloudx.env` files; on an existing install add one
   yourself (`echo "METRICS_TOKEN=$(openssl rand -hex 24)" | sudo tee -a /etc/cloudx/cloudx.env`) and restart the APIs.
   If it is unset, `/metrics` stays open. Put the same value in `/etc/prometheus/metrics_token` (the scrape config
   reads it with `credentials_file`).
2. Reinstall/update the `shared` package on each node (`/metrics` check lives in `shared/metrics.py`) and install the
   updated `cloudx-billing-worker.service` (adds `StateDirectory=cloudx-billing`).
3. `billing-api` now reads `CORS_ORIGINS` like event-api (default `http://localhost`, `*` ignored).

## Billing
- Resources deleted between two worker runs are no longer lost: the worker keeps a snapshot of what it saw
  (`/var/lib/cloudx-billing/seen.json`) and bills a vanished resource until the middle of the interval. The
  estimate is off by at most half an interval; a failed listing never counts as a deletion.

## Events
- The actor of an event is the token's `sub` (tokens have no `user_id` claim; the fallback was dead code).

## Unchanged / known limitations
- Events without `project_id` are visible to admins only and trigger no webhook (by design).
- The `load_balancer` rating (750 IDR/hour) is still a placeholder.
- Other APIs (auth, compute, image, ...) still allow CORS `*`.
