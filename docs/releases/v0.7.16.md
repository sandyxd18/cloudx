# CloudX v0.7.16

Fase 2 release (internal milestones v0.7.14 to v0.7.16): Orchestration, Load Balancer, Telemetry/Alarms/Billing. There are **upgrade steps**.

## Upgrading from v0.7.13
1. Run `cloudx-db-migrate` on the controller: `orchestration_0002`, load-balancer migrations, `telemetry_0002`.
2. Restart `cloudx-orchestration-api`, `cloudx-load-balancer-api`, `cloudx-networking-api`, `cloudx-telemetry-api`, `cloudx-billing-api`, and `cloudx-lb-worker` on compute nodes.

## Orchestration (v0.7.14)
- Heat-like stacks: template validation, dependency-ordered create/delete, rollback, stack events, resource list. Async in threads.
- Update only adds or removes resources.

## Load balancer (v0.7.15)
- NLB (OVN native, L4) and ALB (HAProxy in a netns on a compute node, run by `lb-worker`; L7 path/host policies, health check, TLS).
- TLS certificate keys reach only the `lb-worker` node (mode 0600) through the internal agent endpoint; never in the public API.
- Router `routes` nexthop must lie in an attached subnet or the external network; trunks, routing and VPN are owner-checked.
- Gateway chassis selection prefers the node's own OVS `system-id`.

## Telemetry, alarms, billing (v0.7.16)
- Threshold alarms: `POST/GET/DELETE /telemetry/alarms`, `POST /telemetry/alarms/evaluate` (admin). avg(metric) over `period` seconds vs `threshold`; states `ok` / `alarm` / `insufficient_data`. Evaluated every `alarm_interval` seconds (default 30) under a Postgres advisory lock. Each change publishes `telemetry.alarm.state_changed` on `cloudx.events`; route it to a webhook with an event subscription.
- Retention: raw samples are kept `metrics_retention_days` (7), then folded into hourly rollups (min/max/avg/samples) kept `rollup_retention_days` (365). Read with `GET /telemetry/rollups?metric_type=&granularity=hour|day`. The cleanup endpoint now runs the rollup first.
- Billing: seed rates come from `billing_rate_vcpu|ram|volume|floating_ip|load_balancer` (only when the sheet is missing); change live with `PATCH /billing/rating-sheets/{id}`. The LB rate default is still a 750 IDR placeholder, one rate for NLB and ALB.

## Known limitations
- Neutron names are globally unique, not per project.
- Evacuate does not clean the old domain while the source worker is alive.
- LB: `POST /pools/{id}/sync` works for server-group pools only; no haproxy HA (one host per ALB); NLB clients on the same L2 as the VIP do not work (hairpin); networks joined to the router after the last apply are covered on the next apply; no floating-IP test; NLB `ROUND_ROBIN`/`LEAST_CONNECTIONS` are hash-based (true algorithms only on ALB). The TLS handshake through haproxy was not demonstrated (config and 0600 PEM only).
- Alarms: no evaluation-period smoothing, no alarm history, no per-alarm webhook (use event subscriptions), statistic is avg only. Rollup is Python-side per run; a late sample may add a second row for a bucket (readers merge).
- Stacks: no in-place property update, autoscaling group or nested stack; a restart mid-run leaves a stack `*_IN_PROGRESS`.
- No CLI or dashboard for stacks, LB or alarms.
- Not verified on a VM: OVN IPv6 drop ACL, volume contents after a revert, installer scripts. `tests/scripts` fail on Windows (CI/WSL only).
