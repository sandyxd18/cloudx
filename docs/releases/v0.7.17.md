# CloudX v0.7.17

Closes most limitations carried over from v0.7.5 to v0.7.16. There are **upgrade steps**.

## Upgrading from v0.7.16
1. Run `cloudx-db-migrate` on the controller: `networking_0004`, `compute_0003`, `telemetry_0003`.
2. `database_url` must now be set in `cloudx.conf`. Services refuse to start on the built-in `cloudx:cloudx` default unless `CLOUDX_ALLOW_DEFAULT_DB=1` (lab only).
3. `cors_origins` never accepts `*`; set `CORS_ORIGINS` to the dashboard origin(s).
4. Restart all services and workers (compute-worker on every node).

## Changes
- **Neutron**: names are unique per project (`UniqueConstraint(project_id, name)`) on 11 models; an admin lookup by an ambiguous name returns 409. `Router.project_id` is stored and used for peering/BGP ownership (legacy rows fall back to inference).
- **Nova**: migrate/evacuate accept servers with data volumes; cold migrate keeps the original status (SHUTOFF stays SHUTOFF); `os-instance-actions` records `result`, `message`, `finish_time`; a compute-worker destroys stale libvirt domains of servers that now live on another host (disks and volumes are never touched).
- **Orchestration**: stacks left `*_IN_PROGRESS` by a restart become `*_FAILED` (`interrupted by service restart`); in-place update where the resource supports it, otherwise replacement; `Cloudx::AutoScalingGroup` (`size`).
- **Load balancer**: `POST /pools/{id}/sync` works for pools without a server group.
- **Telemetry**: alarms get `evaluation_periods`, `statistic` (avg|min|max|sum|count) and `GET /telemetry/alarms/{id}/history`; rollups merge into an existing bucket row and use `date_trunc` on PostgreSQL.
- **Billing**: per-type LB rates (`load_balancer_nlb` 750, `load_balancer_alb` 1000 IDR/h, fallback to `load_balancer`; conf `billing_rate_load_balancer_nlb|alb`); the billing worker remembers resources seen in earlier passes (`seen.json`) and bills a resource deleted mid-hour for half the interval.
- **Placement**: fixed a UniqueViolation on every inventory refresh (PUT inventories deleted and re-inserted in one flush). It had been logging every ~10 s since before v0.7.16.
- **Security**: shared CORS helper; DB credential guard.

## Known limitations
- Service-to-service calls still log in as admin (7 workers/services, 20+ endpoints). Design: `X-Internal-Token` + `InternalAuth` on the called endpoints.
- Mid-hour billing is a half-interval estimate (APIs do not return `deleted_at`).
- LB: no haproxy HA; NLB clients on the VIP's L2 do not work (hairpin); networks joined to the router after the last apply are covered on the next apply; no floating-IP test; NLB ROUND_ROBIN/LEAST_CONNECTIONS are hash-based; TLS handshake through haproxy not demonstrated.
- Stacks: no nested stacks; in-place update covers only a few properties.
- No CLI or dashboard for stacks, LB, alarms or role assignments. Domains are labels only.
- VPN, BGP, scheduled snapshots, K8s engine remain control-plane records (Fase 3; volume replication became real in v0.7.19, see its limitations there).
- Not verified on a VM: OVN IPv6 drop ACL, volume contents after a revert, installer scripts. `tests/scripts` fail on Windows.
