# CloudX v0.7.18

Closes the small and medium limitations listed in v0.7.17 and removes the admin-password login between services. There are **upgrade steps**.

## Upgrading from v0.7.17
1. `internal_token` must be set in `/etc/cloudx/cloudx.conf` on every node (the installer already generates it). Workers no longer log in with `auth_admin_password`; without the token their calls get 401.
2. Run `cloudx-db-migrate` on the controller: `load_balancer_0003` (`lb_agent_hosts` table) and `orchestration_0003` (`parent_id` column on stacks).
3. Re-apply existing security group ACLs to replace broken `!nd` drop rules with plain `ip6` (done on the lab; on other installs happens when SG rules change or networking-api bootstrap re-applies).
4. Copy the new `services/` (including `services/shared`) to every node and restart all services and workers (`lb-worker` on compute nodes). `shared/service_client.py` was removed.

## Changes
- **Security**: service-to-service calls (billing, telemetry, event, orchestration workers; load-balancer API; compute and block-store) authenticate with `X-Internal-Token` instead of logging in as admin. The endpoints they call accept it through `UserOrInternal`; every other endpoint stays JWT-only, and the token is never accepted when `INTERNAL_TOKEN` is unset. `auth_admin_password` is now used only by the auth service and the dashboard login.
- **Load balancer**: an NLB reached through a floating IP now works (the FIP is registered as a second VIP on the OVN `Load_Balancer`; before, the router DNATed it past the LB match and the packets were dropped). NLB attachments are reconciled every ~10 s, so networks joined to the router later are covered without a re-apply. Verified on the lab: NLB and ALB through a floating IP from an external client, ALB HTTPS handshake (TLS 1.3, served certificate CN matches), same-L2 NLB clients and a member calling its own VIP (hairpin) both work.
- **ALB HA failover**: active/standby failover using `lb_agent_hosts` heartbeat table (migration `load_balancer_0003`), `LB_FAILOVER_TIMEOUT` (30s), failover guard when no host is alive, `lb-worker` tears down unowned `qlb-*` netns/OVS ports, event `load_balancer.failover`. Live: 35 s failover, no duplicate binding, no flapping. (Active/standby failover: ~35 s outage, in-flight connections dropped, not full HA).
- **Billing**: a resource deleted mid-hour is billed to its exact deletion time taken from the event log (servers, volumes, floating IPs, load balancers); the half-interval estimate remains only as a fallback when no delete event exists. The load-balancer API now publishes `load_balancer.delete`.
- **Orchestration**: nested stacks (`OS::Heat::Stack` / `Cloudx::Stack`, depth max 3, `parent_id` migration `orchestration_0003`, `get_attr` outputs, cascade delete, rollback). Wider in-place update support (Server `user_data`/`flavor` resize, Volume `extend`, Router `routes`, SecurityGroup rules, FloatingIPAssociation, ASG; matrix in `engine.update` docstring).
- **CLI**: new `cloudx stack` (create, update, delete, list, show, resources, events, outputs, suspend, resume) and `cloudx alarm` (create with `--statistic` / `--evaluation-periods`, list, show, history, delete). Added `cloudx role-assignment` (list/create/grant/delete/revoke), `cloudx load-balancer certificate/l7policy/l7rule`, and `cloudx load-balancer listener --certificate`. Added API `DELETE /load-balancers/{lb}/certificates/{id}` (409 while used by a listener).
- **Networking**: fixed IPv6 drop ACL where `!nd` could not be compiled by ovn-controller and prevented flow installation; now plain `ip6` drop (OVN built-in flows keep ND working). Live-verified: ping -6 100% loss, ND REACHABLE, IPv4 fine.
- **Verification**: live-verified on the lab: ASG scale out/in after the internal-token change, volume contents after revert-to-snapshot, and IPv6 drop ACL. Local test suite: 370 tests passing.

## Known limitations
- LB: ALB HA is active/standby failover (~35 s outage, in-flight connections dropped), not full hitless active/active HA. NLB `ROUND_ROBIN` / `LEAST_CONNECTIONS` are hash-based (OVN has no connection counter; use an ALB).
- Domains are labels only (no isolation boundary).
- No dashboard pages for stacks, LB, alarms, or role assignments.
- Fase 3 items remain control-plane records only: K8s engine, VPNaaS, BGP/VPC peering, volume replication, scheduled snapshots.
- Installer scripts not verified on a VM; `tests/scripts` fail on Windows (CI/WSL only).
